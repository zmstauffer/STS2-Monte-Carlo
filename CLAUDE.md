## Goal

An advisor for Slay the Spire 2 that helps with **run-level decisions**: card rewards (including skip), map pathing, shops (buy / remove), events, and rest sites. It does **not** give turn-by-turn combat advice.

Every recommendation is justified with Monte Carlo simulation, with a horizon of **the end of the current act**, and explained in plain language (e.g. "Option A survives Act 1 slightly less often but wins 20% more Act 2 elite fights").

## Architecture (decided)

1. **Mod ("eyes")** — this repo's `SpireMonteCarlo` project, forked from `ebadon16/sts2-advisor`. Harmony hooks detect decision screens and read run state (deck, relics, potions, HP, gold, floor, visible map). Later it sends that state to the app over local IPC (socket or named pipe) and draws recommendations in its existing Godot overlay. Keep the mod thin: capture and display only.
2. **Standalone app ("brain")** — a separate C# process (to be created in this repo). Holds the simulator, rollout loop, scoring, and explanation text. Must be testable without the game by loading saved state snapshots. Kept out of the game process so heavy CPU work can't stutter or crash the game, and so game patches break less.
3. **Data** — a local cache of Spire Codex data (see below), stored under `%APPDATA%\SpireMonteCarlo\`, refreshed when the game version changes. Replaces the original repo's hand-made tier JSON files.

## Simulator design notes

- Rollouts still need an **automated combat player**. A simple heuristic bot is fine: absolute win rates will be off, but comparisons between options are what matter. Compare options using **common random numbers** (same seeds for each option) to reduce noise.
- One rollout: from the current state, walk a path on the visible map to the act boss. Sample combats from the act's encounter pools, sample `?` rooms from event/room odds, and resolve future decisions with default policies:
  - Card rewards: sample picks using **Codex Elo** as a Bradley-Terry model (per-character slice, stronger-player bracket such as `wr50` or `a10`). Need a rule for Skip if Skip isn't in the Elo data.
  - Rest sites: rest below ~50% HP, otherwise upgrade.
  - Shops: enumerate affordable bundles (including card removal), prune implausible ones using Elo.
- **Scoring** each rollout: survived the act, HP at act end, plus a short "probe" where the end-of-act deck fights a few sampled next-act elites. Survival alone undervalues scaling cards, since nearly everything survives Act 1.
- **Performance**: expect tens of thousands of simulated fights per decision. Use a lean engine with plain structs and no Godot dependency.
- **Open question to spike early**: can the game's own combat logic in `sts2.dll` run headless outside Godot? If it's tangled with nodes and animation, write our own lean combat engine and use the game/Codex data for numbers. Expected outcome: our own engine.
- **Calibration**: compare the bot's simulated damage taken and fatal rate per encounter against Spire Codex `/api/runs/encounter-stats`.
- **First milestone**: one character, Act 1 only, card reward decisions only. That exercises the whole pipeline with the least content to encode. Pathing and shops come after.

## Spire Codex (data source)

- Site: https://spire-codex.com — API base `https://spire-codex.com/api` — source: https://github.com/ptrlrd/spire-codex
- Their data is extracted from the decompiled game (regex parsers over the C# source), so spot-check unusual monsters/events against our own decompiled copy before trusting them in simulation.
- Useful endpoints:
  - `GET /api/exports/eng` — ZIP of all entity JSON (limited to 10/hour). Use this for the local cache.
  - `GET /api/cards`, `/api/relics`, `/api/potions`, `/api/monsters` (HP, move state machines, intents, attack patterns), `/api/encounters?act=&room_type=`, `/api/events` (decision trees, outcomes, preconditions), `/api/acts`, `/api/powers`
  - `GET /api/merchant/config` — shop pricing
  - `GET /api/runs/metrics/{cards|relics|potions}?bracket=all|solo|a10|wr30|wr50|wr75|...` — Codex Score, Codex Elo, win rate, pick rate, per-act splits
  - `GET /api/runs/scores/{type}?character=&bracket=` — Score + Elo per entity; relics accept `?act=`
  - `GET /api/runs/encounter-stats` — per-encounter fatal rate, average damage, turns
  - `GET /api/history/{entity_type}/{entity_id}` — per-entity patch history
  - `?channel=beta` serves Steam public-beta data
- Two metrics:
  - **Codex Score**: Bayesian-shrunk win rate. Known biases (staples sink, late rares float). Use only as a sanity check.
  - **Codex Elo**: Bradley-Terry fit on reward screens (taken card beats skipped cards). Largely skill-agnostic revealed preference. Use as the rollout pick policy.
  - Neither is ground truth. Where our simulation disagrees with Elo for a specific deck, that's either a bug or the most valuable advice the app gives.
- Rate limits are per endpoint: 15/min with no key, 60/min with a free key sent as `X-API-Key`. Never call the API during a decision; read from the local cache.
- License: Spire Codex source is PolyForm Noncommercial; the hosted API is free within rate limits; game data is © Mega Crit. This project is personal and noncommercial.

Simulator decisions (owner, from the design discussion):

- First milestone character is Ironclad; default Elo bracket is `a10`.
- The combat bot should be a middle ground: smarter than "highest damage first" (it weighs incoming damage, block, energy efficiency, and card synergies at a basic level) but not a search-based player. Only comparisons between options matter, so calibrate it against Codex encounter stats rather than chase absolute accuracy.
- Card-reward skips are not a flat rate. The chance of skipping should rise as the deck fills and as a card fits the deck worse: few skips early, more later. The Codex per-act pick rates (`pick_rate_by_act`) and the ~35–38% overall skip rate are calibration targets, not the rule itself.
- Rest sites: rest below ~50% HP, otherwise upgrade.
- Speed matters: the simulation must run many fights per decision, so it needs to use all CPU cores.
- Engine: chosen and built as a lean own engine (`SpireMonteCarlo.Sim`), data-driven from Codex plus the decompiled game. The game's own combat code can't run outside Godot (see `spikes/headless-combat/README.md`).

Simulator status (an end-to-end pipeline exists, but it is not yet trustworthy enough to act on):

- What exists: `advisor advise <snapshot>` runs thousands of simulated futures of the rest of the act for each offered card and for skipping, on shared random seeds, and reports survival, HP left, the paired difference from skipping and its uncertainty. About 40,000 whole-act rollouts per second on all cores. Supporting commands: `advisor sim extract` (reads the decompiled game), `sim fight`, `sim encounters`, `sim calibrate`, `sim calibrate-run`.
- Engine rules follow the decompiled game (damage/block math, debuff timing, Ritual skipping its first trigger). Card effects are derived automatically from Codex numbers (`CardLibrary`), with `Approximate` set on cards whose text says more; `Overrides.cs` holds hand fixes (only Body Slam so far).
- Monster AI is extracted from the decompiled classes (`MonsterAiExtractor`): weighted random branches, repeat rules, staggered starts, alternate starts. Codex's own state machines are unreliable (missing links and weights). Encounter lineups come from the decompiled encounter classes, with the 6 random Act 1 ones written by hand in `EncounterLibrary`. Extracted data is only ever written to the local cache.
- The game decides the act's upcoming encounters when the act starts (`ActModel._rooms`), so snapshots now carry an `ActPlan` (remaining normal/elite encounters in draw order, boss, second boss) and the live `Odds` counters. The rollout uses them when present and samples otherwise.
- Rollout policies: route chosen by a value DP over the map plus randomness; rest below 50% HP else upgrade the best card; card rewards picked by Bradley-Terry over a10 Elo with a skip option whose Elo grows with deck size (fit to the Codex per-act skip rates: about 25% Act 1, 42% Act 2, 52% Act 3); `?` rooms roll with the game's real odds. Shops, potions, relics, elite/chest relics, and gold are modelled (see below); events and the Ancient boon at act start are not. Since then: the route DP values early monsters (card rewards) and avoids early elites, rests at <60% HP (<90% at the rest site right before the boss) else upgrades; a run from the start of Act 1 takes one of Neow's boons first (`NeowBoons.cs`: two offered positive boons, the typical player takes the one it likes better; all 19 positive boons are written from the decompiled relics; the cursed options and Massive Scroll are not modelled; `ActRollout.DefaultNeow` turns it off, and an Ancient/Neow choice snapshot evaluates the options instead).
- Calibration: against real Ironclad encounter stats, normal fights track well (rank correlation ~0.75) but elites and bosses do not (~0.1 and ~0.3). The raw simulated player is far weaker than a real one (Act 1 survival ~8% vs ~65%), so the rollout multiplies the player's HP pool by `ActRollout.PlayerHpScale` (now 2.5, see below) as a stand-in for everything unmodelled. Scaling the HP pool (not enemy damage) keeps self-damage cards like Offering priced consistently. A value closer to 1.0 would mean a better model.
- Elite and boss mechanics are modelled (rules read from the decompiled power and monster classes, each pinned by a test in `MonsterMechanicsTests` and spot-checked with `sim fight --trace`): Slow, Territorial, Asleep (Lagavulin, incl. waking by damage), Minion (fight ends when the non-minions die), Skittish, Infested (spawns 4 Wrigglers), Hardened Shell, Slippery, Intangible, Shriek and Plow (HP-threshold stun and phase change), Vigor, Ringing (one card per turn), Steam Eruption (the Waterfall Giant becomes untouchable and explodes), plus stuns, monsters starting on an alternative move, and the status cards monsters hand out (Wound, Dazed, Slimed, Infection, Burn, Toxic, Beckon, ...; extracted from the move methods, including ascension-dependent counts, and Burn/Infection-style end-of-turn damage on cards). Monsters now pick their next move after the round's end-of-turn effects, like the game. Every Act 1 elite and boss is free of ignored powers; 7 ordinary monsters still ignore one small power each (Ravenous, Suck, Surprise, Smoggy, Constrict, Tangled).
- With the mechanics in, a decent hand-built 15-card deck at the calibrated HP beats every Act 1 elite and boss essentially every time and takes damage within ~30% of real players. (That was before the card recipes were completed; the reward policy now builds real decks, see below.)
- Card recipes are now hand-checked for every Ironclad card (`CardRecipes.cs`; `IroncladCardTests` pins each one). `sim rewards` shows ~1% of picked cards as approximate.
- The bot plans a whole turn (`BasicBot.Plan`): it searches orders of card plays and potion uses on cloned combats (`Combat.Clone`), scoring each play with the old per-play valuation and summing, then executes the plan and re-plans when a draw changes the hand. Bounded by `MaxDepth`/`BranchWidth`/`NodeBudget`; default budget 30 nodes / width 3 / depth 6 (matches the old 120/4/8 results at ~2x the speed; `sim fight --nodes/--width/--depth` to experiment; greedy play, 1/1/1, is only ~5% worse but 3-4x faster). Cloning shares card objects that nothing can change in place (`Combat._cardsChangeInPlace` covers Stomp, Rampage, Thrash). The advisor runs with the server GC (~40% faster). `advise` on a card reward (4 options x 2000 futures) takes about 4 s. Planning uses a perturbed copy of the RNG so it never sees the real draws.

The rollout carries the snapshot's potions (3 slots), rolls drops with the game's `PotionRewardOdds` (0.4 base, +0.125 elite bonus, ±0.1 pity) and the 65/25/10 rarity split, and treats a drop of an unmodelled potion as no drop. Shop rooms (and `?` rooms that roll a shop) generate the merchant's stock as `MerchantInventory` does (5 class cards incl. one on sale, colorless uncommon+rare, 3 relics, 3 potions, removal 75 +25 each / 100 +50 from A6) and the default player removes Strikes/Defends first, buys a relic that does something, then cards Codex Elo favors, then potions. - Bot ceiling on bosses: with a decent 19-card deck at 300 HP the exhaustive-lookahead player loses ~30% less HP than the leaf bot in Lagavulin Matriarch/Kin/Vantom (79/55/63 vs 105/85/85, real players average ~50), and neither wider search, more finalists, Steps-style whole-turn counting nor judging the finalists by rollouts closed it, so the gap is in the plan value function (or in candidate plans it never ranks well), not in search width. Two fixes came from `sim fight --audit R` (plays a fight, and each turn compares the bot's plan with the best ordering of the hand by rollouts): the leaf ignored card draw, so cycling cards (Shrug It Off, Battle Trance, Pommel Strike) were undervalued (`DrawValue` 6), and a plan that stops on a draw wastes the energy it leaves although the turn is planned again (`ReplanEnergy` 8); together they cut boss HP loss ~15% (79.6 to 67.6 on the bench, exhaustive ~65). Leaf weights are now fit by regression: `advisor sim fitleaf [--n seeds] [--rollouts R] [--room ..] [--out rows.csv | --in rows.csv] [--tune ..] [--loss choice|ls]` plays the bench fights, takes the plans the bot's search considered each turn, records the leaf's terms (`LeafFeatures`: HP lost in the enemy phase, future threat cost, enemy HP, cards drawn, replan energy, powers gained, wasted energy, enemy Vulnerable/Weak, enemies alive, exhausted statuses/other cards, player debuffs, HP the plan itself costs), finishes the fight from each plan 64 times on shared shuffled futures, and fits the weights to that. Plain least squares predicts values better but chooses worse (it is dominated by clearly bad plans), so the default loss is a softmax "soft choice" fit by gradient ascent from the current weights. It reports, on held-out fights, how much HP the old and new choices lose against the best plan of each turn, with a noise floor from split rollouts. Two rounds (the second collected with the first round's weights) converged; the bot's real error is ~0.7 HP per turn against the best of the plans it considers (1.17 vs a 0.46 noise floor), spread evenly over fights, and linear weights on these terms only close a sliver of it (bench 256.5 -> 254.4: normal -6%, boss -2%, elite +2%). So the leaf is near what re-weighting can do; further gains need new information in the leaf or better candidate plans. The fit also found a real bug: `Combat.HpLost` counted overkill (a death from 11 HP to -69 counted 80), which made deaths to big hits (the Waterfall Giant's explosion) look far worse than other deaths in bench/rollout scores; it is now capped at the HP left.
- A rollout could hang forever in Pillage (draw until a non-attack) when Hellraiser played every drawn Strike so the hand never filled; the draw is now capped (regression test in `NeowAndMapTests`). `calibrate-run --watchdog` names rollouts running longer than 10 s and `--only N` replays one Act 2 rollout printing each fight (`ActRollout.TraceFights`); `dotnet-stack report -p <pid>` (global tool) shows where a hung process is.
- Bot quality: `BotTuning` holds the bot's valuation weights (`BOT_TUNE="Name=value,..."` env var); `advisor sim bench [--room normal|elite|boss] [--tune ..]` scores the bot on a fixed suite (3 decks x Act 1 fights, lower is better) and `sim tune` coordinate-descends the weights. `sim fight --exhaustive R` (and env `BOT_EXHAUSTIVE=R` for any command) plays each turn by trying every ordering of the hand and finishing the fight from each with R shuffled-future rollouts; it is ~5000x slower, research only. With it a whole Act 1 run reaches real survival at scale 2.0 instead of 2.5, and it shows the old additive per-card scoring lost 10-25% more HP in elites and up to 60% more in weak fights. The default bot now uses "leaf" mode (`Leaf=1`): every plan is judged by playing the enemy phase on a copy (`Combat.EndPlayerTurn(startNextTurn: false)`), then pricing what is left: HP lost now, plus for each enemy its damage per turn (from its intent and a `Horizon`-turn pass-through simulation, floored at `BaseThreat` of its average attack) times the turns until it dies when enemies are killed highest-damage-per-HP first (`Dpt`, damage per turn, sets the turn length), with extra HP counted for Infested and Surprise spawns, Vulnerable worth a third of our damage while it lasts, a small `Progress` term per enemy HP, the value of powers gained, and a Sandpit penalty. The best `Finalists` plans by the cheap judgement get the multi-turn judgement. This cut normal-fight HP loss ~25% and elites ~5%, at ~2.7x the planning time (`advise` on a card reward: ~11 s for 4 options x 2000 futures). Set `Leaf=0` for the old scorer. Gotcha: `ParseDeck` accepts ids that do not exist for the class (there is no Ironclad Cleave in v0.111); they become do-nothing approximate cards, so check the `approximated cards` line of `sim fight`.
- Other known gaps: the bot is weak against "many small hits" mechanics and against fights that need setup across turns (see Act 2 status); the Ancient boon at act 1, treasure gold, Act 3 content, and most rare/ancient relics are not modelled. The map fixtures are Regent ones; an Ironclad map would calibrate better.

Exhaust and draw cards (owner asked to fix Burning Pact, Havoc, True Grit, Expect a Fight; `sim cardvalue --deck starter` showed them below a dead card):

- Flow: when `SnapshotExporter` writes a snapshot (`SnapshotExporter.LastFile`) the panel shows "Thinking..."; it polls `advice\latest.json` and `advice\status.json` 4 times a second (re-reading only changed files) and shows the suggestion, up to 7 options (best highlighted, "~ equal" ties, "-3.2" points behind) and two Why lines once the advice's `snapshot_file` matches. Other states: "Nothing to advise on this screen", the advisor's error, "The advisor isn't running" (heartbeat older than 12 s, or no status file), "Waiting for the next decision" once a card or relic is picked (late advice for a decision already made is ignored), and the run result. While thinking it counts the seconds since the screen appeared ("Thinking... 12s"). Hidden during combat until the next decision screen. Drag the title to move (position saved in `overlay_settings.json`), double-click or the arrow to collapse, F7 / Alt+H / ` to hide.
- The watcher writes `advice\status.json` (`Contracts.WatcherStatus`: snapshot, state thinking/done/unsupported/error, message, heartbeat every 3 s while idle; deleted on Ctrl+C) and writes status and advice files atomically (temp file + move). `AdviceOption.Display` names options as a player would (card names; map nodes by room and position among the choices, "Elite (left)", `AdviceFormatter.DisplayLabels`), and the suggestion uses those names. `AdviceDisplayTests` pins them.
- Gotcha found in the first in-game test (the panel sat on "Waiting for a decision"): the mod is built with the plain .NET SDK, without Godot's source generators, so Node subclasses defined in the mod are never registered as scripts and Godot never calls their `_Process`/`_Input`/`_UnhandledKeyInput` (the old overlay's `OverlayInputHandler`, F7 hotkey and stale-screen check never ran either; its content was pushed by the hooks). Anything per-frame must hook a signal with a C# delegate instead: the panel uses `SceneTree.ProcessFrame` and polls the hide hotkeys with `Input.IsPhysicalKeyPressed`. Control signals such as `GuiInput` work the same way.
